# 복수 사업 연결 개선 결과

## 구현

- Applyhome.catalog(): 최근 180일 공식 사업 목록을 이름 필터 없이 페이지 조회하고 한 실행 안에서 재사용한다. 지역은 확정 매칭 단계의 주소 근거로 검증한다.
- expand_projects(): 배정표의 사업 문맥 또는 주소의 복수 블록을 기준으로 기관추천 공고를 사업별 레코드로 분리한다. ID는 원공고 ID와 주택관리번호·공고번호 조합이다.
- 분리된 사업에만 해당 배정 세대를 연결하며, 미해결 사업의 배정은 원공고에 남긴다. 공식 모델만 있는 사업에는 배정물량을 생성하지 않는다.
- `95, 99번지` 같은 명시적 지번 목록은 각 지번으로 검증한다. 인접 지번이나 다른 시군은 허용하지 않는다.
- 후보 중복은 자동 선택하지 않는다. 반복 실행 및 기존 분리 레코드와의 중복을 방지한다.
- 정확한 타입 연결 뒤 기존 면적대 가격 범위 기능을 적용한다. 서로 다른 사업의 가격은 섞지 않는다.

## 실제 저장 응답 재현

실행: `.venv/Scripts/python.exe -m scripts.verify_matching_capture`

동일한 2026-10-18 공식 응답을 사용한 로컬 비교:

| 지표 | 기존 | 개선 |
|---|---:|---:|
| 분양가가 있는 사업 | 6 | 9 |
| 분양가가 있는 주택형 | 24 | 31 |

추가 사업: 아크메르 동탄 95(2개 타입), 힐스테이트 고덕엘리스트 A12(3개 타입), A65(2개 타입).
아크메르 95의 배정물량 84C 4세대, 84F 2세대는 기존 공식 배정표 추출값을 유지한다. 99 사업에는 95 가격을 넣지 않는다. 고덕엘리스트는 장애인 배정 미확인으로 차익을 보류한다. 정확한 전용면적이 미확인인 주택형도 차익을 보류한다.

백엔드 테스트 62개 통과. 실제 응답 재현 결과는 matching-improvement-results.json. 모의 거래를 운영 데이터에 넣지 않았다.

## 남은 범위

신규 인증 API 실조회, GitHub 반영 및 운영 사이트 배포는 이번 실행에서 수행하지 않았다. 저장 응답 9개 사업은 과거 검사기의 이름 필터를 거친 표본이므로, 전체 최신 API 기준 매칭 증가량과 시세차익 증가량은 아직 검증하지 않았다. 운영 docs/data/latest.json을 재현 데이터로 덮어쓰지 않았다.
