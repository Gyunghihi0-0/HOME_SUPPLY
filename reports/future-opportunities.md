# 미래 특별공급 기회 중심 개선

기준 main: d69fbf08a9779a0e9ccd6daf06fe02e59c8a2355. 기존 운영 JSON 30개 사업 레코드·가격차 17개 유형은 수정하지 않았다. 분석 정책·데이터 계약 1.0.0도 유지했다.

## 1단계: 수집 안정화

실행 39140783354는 PR #9 병합 커밋 09f724a에서 시작했다. 로그의 15:30:56 notice_stage_start 이후 체크포인트 없이 15:32:56 외부 120초 제한에 걸렸다. 어느 네트워크 요청 또는 문서가 정지했는지는 기존 로그로 확정할 수 없다.

- 목록 조회 전의 불필요한 게시판 전체 HTML 다운로드를 제거했다. robots 규칙은 계속 확인한다.
- 신규·접수 중·예정·일정 미확인 공고를 종료 공고보다 먼저 처리한다. 같은 우선순위에서는 이전 처리시각이 오래된 공고부터 확인한다.
- 본문 확인 직후 첫 체크포인트를 저장하고 첨부 처리 후 다시 저장한다. 저장 건수는 공고 ID로 중복 제거한다. 미완료 페이지와 처리 이력은 기존 재개 파일에 보존한다.
- 첨부 URL은 매번 조건부 요청으로 재검증한다. ETag/Last-Modified가 있고 서버가 304를 반환할 때만 다운로드를 재사용한다. 검증자가 없으면 다시 다운로드한다. 변경된 바이트는 새 해시로 다시 파싱한다.
- 파싱 성공 결과만 콘텐츠 해시·확장자·파서 버전으로 캐시한다. 문서 파싱은 별도 프로세스에서 최대 8초로 제한하고, 스트리밍 수신에도 전체 수집 예산을 검사한다. 기존 80초 예산과 외부 120초 제한은 늘리지 않았다.
- 운영 Summary는 명시적 운영 플래그와 실제 운영 출력 경로가 모두 맞을 때만 생성한다. pytest 단계의 Summary 경로는 비워 가상 공고 집계가 운영 현황에 나타나지 않게 한다.

## 2단계: 화면

기존 레이아웃을 재사용한다. 기본 장애 정도는 경증이다. 현재·미래 공고와 과거 기록을 나누고, 신청 요건·정확한 공식 가격·검증 좌표가 확인된 접수 중/예정 양수 가격차를 우선한다. 나머지는 접수 중→접수 예정→일정 확인 대기로 구분한다. 명시적으로 가격 미연결·음수·표본 부족·편차·좌표 부족을 표시한다.

양수 필터는 음수·미확인 자격·과거 공고·세부 타입이 모호한 면적대 가격·첨부 재검증 미완료를 제외한다. 현재 데이터에서는 조건을 만족하는 양수 공고가 없다는 문구를 표시한다. 가격차 큰 순 정렬, 개별 거래 근거와 신뢰도는 기존 데이터를 재사용한다.

기관추천 시작/마감·신청 방법의 공식 공고 링크를 바로 표시한다. 청약홈 실제 청약기간과 혼동하지 않도록 별도 확인 항목을 둔다. 법적 제한은 추정하지 않고 미확인으로 표시한다. 입주예정 연도 활용·표본·기존 주택 차이·세금/옵션/금융비용·매도 시점의 한계도 명시한다.

- 실제 기존 JSON의 데스크톱/모바일 브라우저 검사 통과: 검색/초기화, 장애 정도, 과거 기록, 양수 없음 문구, 모달 키보드·포커스, 가로 넘침 없음, 로딩 실패 보존.

## 남은 범위

실제 GitHub 수집 완료 시간·완주 여부는 이번 변경으로 운영 수집을 실행하지 않았으므로 미검증이다. DNS/서버 장애 자체를 해결했다고 주장하지 않는다. 서버가 조건부 요청을 지원하지 않으면 첨부 다운로드는 여전히 필요하다.

기관추천 공고 외 별도 공식 미래 사업 목록의 자동 발굴, 분양가 없는 단지의 독립적인 주변 가격대 수집, 개별 전매/거주/재당첨 조건·당첨 이력 제한의 구조화된 자동 검증은 미구현이다. 해당 정보가 없을 때 신청 가능·가격차를 만들어 내지 않는다. 기존 미매칭 사업·공식 좌표 부족 문제도 이 PR에서 확대 조사하지 않았다.

예약 오전 6시(KST)·수동 실행과 push 시 수집/배포 금지 설정은 유지한다. CI 통과 후 코드 병합을 검토할 수 있으며, 실제 수집 정상화 판정은 별도 운영 검증이 필요하다.
